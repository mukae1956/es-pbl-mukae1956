## (개인·필수) 문제 1 — 사용자와 판단 하나로 좁히기

### 답안

- 내 주제: Elasticsearch로 OTT 콘텐츠 키워드 검색 서비스
- 한 문서의 의미: 콘텐츠(영화/시리즈) 1건
- 사용자 한 명: OTT 서비스 콘텐츠 운영 담당자
- 사용자가 반복해서 하는 일: 장르·평점·시청 가능 여부 기준으로 카탈로그 구성 현황을 점검
- Dashboard를 보고 결정할 것: 콘텐츠가 부족한 장르, 평점이 낮은 구간, 시청 불가 비율이 높은 영역을 파악
- 결정 뒤 수행할 행동: 부족한 장르·평점대 콘텐츠 추가 확보 또는 라이선스 갱신 검토를 요청
- 사용자에게 필요 없는 정보: cast·director 등 개별 문서 상세 정보(카탈로그 현황 판단에는 불필요, Discover에서 확인)

## (개인·필수) 문제 2 — 서로 중복되지 않는 질문 4개

| 번호 | 분석 질문 | 질문의 답으로 내릴 판단 | 다른 질문과 겹치지 않는 이유 |
|---|---|---|---|
| Q1 | 전체 콘텐츠는 몇 개인가? | 카탈로그 전체 규모가 목표치에 맞는지 확인 | 개별 field가 아닌 전체 문서 수만 다룸 |
| Q2 | 장르별 콘텐츠 수는 어떤가? | 특정 장르 편중/부족 여부 판단 | 분류(genre) 기준 비교, 수치 분포·상태와 무관 |
| Q3 | 평점은 어느 구간에 많이 몰려 있는가? | 저평점 구간 콘텐츠 비중이 큰지 확인 | 연속형 수치(rating) 구간 분포를 다룸, 장르 그룹과 다른 축 |
| Q4 | 시청 가능한 콘텐츠 비율은 얼마인가? | 시청 불가 콘텐츠 비율이 높으면 라이선스 점검 필요 | boolean 상태 비율을 다룸, 규모·그룹·수치와 겹치지 않음 |

## (개인·필수) 문제 3 — 질문별 field 존재 여부 점검

| 질문 | 필요한 field | mapping type | 실제 존재 | 값이 충분히 분포 | 가능/가공 필요/추가 필요 |
|---|---|---|---|---|---|
| Q1 | (없음, Records) | - | O | O(1000건) | 가능 |
| Q2 | genre | keyword | O | O(7개 장르, 132~157건씩) | 가능 |
| Q3 | rating | float | O | O(2.0~5.0, 평균 3.54) | 가능 |
| Q4 | available | boolean | O | O(true 690 / false 310) | 가능 |

- 현재 데이터로 바로 만들 수 있는 질문 수: 4
- 선택한 A/B/C 경로: A(개인 데이터로 제작)
- 선택 이유: contents index에 이미 1000건이 적재돼 있고 Q1~Q4에 필요한 field가 모두 mapping·문서에 존재해 별도 보강 없이 바로 제작 가능

## (개인·필수) 문제 4 — 부족한 데이터 생성 규칙 설계

- 답할 수 없는 질문: 월별 콘텐츠 등록(카탈로그 추가) 추이는 어떻게 변하는가?
- 부족한 field: added_at
- mapping type: date
- 예시값 3개: 2025-03-14, 2025-09-02, 2026-01-20
- 범주라면 고유값 수: 해당 없음
- 수치라면 최소·최대·대표 구간: 해당 없음
- 상태라면 예상 비율: 해당 없음
- 날짜라면 기간과 단위: 최근 24개월, 월 단위 집계
- 다른 field와 필요한 관계: 없음(독립적인 등록 시점 필드)
- 한 문서를 생성하는 규칙: 최근 24개월 범위에서 균등 난수로 날짜를 뽑아 각 문서의 added_at에 부여
- 필요한 문서 수와 이유: 기존 1000건 그대로 사용(24개월에 문서당 1개씩 배정하면 월평균 약 40건으로 Line 차트에서 구간별 차이 관찰 가능)
- seed 고정 여부: 고정(재현 가능하도록 generate-data.ps1의 난수 seed 사용)
- 생성 후 검증 방법: 재적재 후 Kibana Date histogram(월 단위)으로 각 월 구간에 값이 0건 없이 분포하는지 확인
